skillbench

skillbench checks agent skills, the instruction files a coding agent loads when a request matches them. It lints each skill file against 26 checks, then reads activation counts from the session history your agent already keeps. Codex CLI and Gemini CLI do not record which skill was active, so their skills are reported as “unmeasured”.

The machine I wrote this linter on scores “poor”. Every finding names the check, the skill and the severity, and every check carries a “why it matters” line and a “how to fix” line. The checks live in one file you can open, and any check you disagree with can be switched off with --ignore.

Install

# once
> /plugin marketplace add halilneed/plugins

# the plugin
> /plugin install skillbench@hailneed

# and try it
> /skillbench:coverage

The marketplace id is hailneed, which is why the install line ends in @hailneed.

  • Claude Code and Node.js 18 or newer.
  • No dependencies, no build step, no API key, no account.
  • It also runs standalone: node scripts/skillbench.mjs --coverage --md --lang en
  • For CI, --lint --path . --out lint.json has a stable output format. Fail the build when score.raw goes above a threshold you set.

Commands

/skillbench:lint

Checks whether a skill is written correctly. The 26 checks cover frontmatter, activation quality (trigger phrases, negative boundary), body size, broken references, portability, tool permissions and eval coverage. It runs on the repo you are developing (--path) or on every skill installed across Claude Code, Codex CLI and Gemini CLI.

/skillbench:coverage

Shows whether a skill ever fires. Claude Code records which skill was active for each tool call. Coverage turns that into real activations per skill (calls, distinct sessions, projects, recency) and lists the skills that never fired, with the likeliest reason. Codex CLI and Gemini CLI do not record attribution, so their skills are reported as unmeasured.

/skillbench:collide

Shows whether two skills compete for the same request. It gives an idf-weighted overlap score that names the shared terms blurring the boundary. It also detects drift in skills mirrored into several agent homes, by checking whether the copies are still identical.

What it does and does not do

  • It makes no network calls. The scanner only reads skill files and session logs already on your disk, and skillbench.mjs contains no fetch and no sockets.
  • Only Claude Code stores skill attribution, so skills on Codex CLI and Gemini CLI are reported as unmeasured and get no count.
  • No quota is spent. Everything is read from disk. Live trigger testing, which means running should_trigger prompts, is deliberately deferred to v0.2 because it costs quota.
  • There are 26 checks and no model judgement. checks.mjs is a list you can read, and --selftest runs the engine against 20 fixtures without touching your data.
  • Symlinks are followed. Skills linked from a development repo are found and linted. A naive scanner silently misses every one of them.
  • MIT-licensed (LICENSE). No account, no signup, no telemetry.

Planned

A hosted version, skillbench Cloud, is planned. The plugin stays free and local.

  • Continuous measurement for a team skill library: lint and coverage tracked over time instead of run by hand.
  • Regression history: how a description change affected the trigger rate, before and after.
  • Pre-publish gate for marketplace publishers: a skill has to pass before it is published.
