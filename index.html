Models

Three small models for personal data in Turkish text. They run on a CPU, so the text can stay on your own machine. Weights, evaluation sets and known failure cases are public on Hugging Face.

Turkish PII detection and masking

270M parameters v02 September 2026

Rewrites Turkish text with the personal data replaced by labels: names, national ID numbers, IBANs, phone numbers, email addresses. You tell it what to mask in a short Turkish instruction. It can mask everything, only the fields you name, or everything except them.

0.944 exact match on a public 1,000-row benchmark. On the 531 rows I kept out of model selection it scores 0.945. The weakest slice is text that mentions several people, at 0.750.

Turkish KVKK classifier

110M parameters MIT

Tells you which kinds of personal data a Turkish text contains. It covers 24 categories: the 14 used in VERBİS, Turkey’s data controller registry, and the 10 special categories in Article 6 of KVKK, the Turkish data protection law.

0.874 micro-F1 on 987 held-out texts, at about 22 ms per text on a desktop CPU. For the question “is there special-category data here?” recall is 0.884, so roughly one in nine of the texts that contain such data is missed.

Evaluation set: turkish-kvkk-classification-benchmark,
987 texts, CC0.

Turkish BSEBY classifier

110M parameters MIT

Built for bank data inventories and data loss prevention (DLP) pipelines. It flags whether a Turkish text contains personal data, special-category data, authentication data such as passwords and card numbers, customer secrets or bank secrets. The classes follow BSEBY, the Turkish regulation on banks’ information systems.

0.944 micro-F1 on 747 held-out texts, at about 32 ms per text on a desktop CPU. The weakest label is authentication data, at 0.873 F1.

Evaluation set: turkish-bseby-classification-benchmark,
747 texts, CC0.

How the PII model got to 0.944

I started from cagrigungor/pii-guard-turkish-270m, a Gemma 3 270M fine-tune that scored 0.740 on the benchmark. Rather than move to a bigger model, I generated 24,000 synthetic examples aimed at the cases it got wrong (uppercase text, long records, numbers written out as words, several people in one text) and kept training. v01 reached 0.882.

For v02 I rebuilt the generator: 53 labels, about 1,500 hand-written templates and 40,000 examples, of which 32,864 were kept after aligning them with v01. The model fine-tuned on those scored 0.844 on its own, below v01, so the released weights are a 50/50 average of the new and old models, which scored 0.944.

Tools

Open-source tools, mostly for people who work with coding agents.

Agent tools

Six Claude Code plugins: agent-blackbox, skillbench, scar, gardener, painradar and devpersona. Five of them read the session logs already on your disk and report what the agent did, with no network calls. painradar reads public complaints on the web.

agentmemora

A local dashboard that reads session transcripts, auto-memory and instruction files to show what your agents know, flag context at risk, and move context between sessions, machines and agents. On npm.

solostacks

An MCP server that pulls live data from Reddit, GitHub Trending and Hacker News and recommends tools for solo developers.

hyperframes-agent-skill

19 rule files that teach a coding agent to write correct HyperFrames (HTML-to-video) compositions.

promptrank

A small browser quiz with five prompt scenarios, scored on clarity, creativity, technical depth and strategy. In Turkish, English and Spanish.
